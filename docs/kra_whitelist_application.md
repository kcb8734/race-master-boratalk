## ■ 2. 활용 서비스 개요

### 2-1. 서비스 목적
「경마통」은 한국마사회(KRA) 공공데이터 API를 활용하여 경주 출전마 분석, 배당률 시뮬레이션, AI 기반 경주 예측 서비스를 제공하는 비영리 정보제공 플랫폼입니다. 이용자가 경마 데이터를 투명하게 열람하고 올바른 경마 문화를 이해할 수 있도록 돕는 것이 목적입니다.

### 2-2. 주요 기능
1. **출전표 실시간 조회** — 경주 당일 출전마 정보, 기수 정보, 배당률 표시
2. **AI 스탯 분석 엔진** — 21개 KRA API 데이터를 연산하여 출전마별 S_speed, S_stamina, S_form, S_track 지표 산출
3. **벌크 동기화 스케줄러** — 매일 새벽 4시 23개 API 데이터 선취득 → 경주 당일 빠른 응답 보장
4. **5단계 폴백 아키텍처** — API 장애 시에도 서비스 연속성 확보 (API→캐시→Mock 순서)
5. **관리자 패널** — API 가용성 진단, 에러 로그 분석, 화이트리스트 신청용 에러 덤프 CSV 내보내기

### 2-3. 호출량 예측

| API ID | API명 | 일일 예상 호출 | 비고 |
|--------|-------|--------------|------|
| API187 | 경마경주정보 | 100~300회 | 경주 목록 조회 (경주장별, 날짜별) |
| API26_2 | 출전마 상세정보 | 200~500회 | 경주별 출전마 목록 (경주당 1회) |
| API4_3 | 경주기록 | 300~800회 | 말별 과거 성적 조회 (출전마당 1~2회) |
| trnweekentry | 조교사 차주 출전 예정마 | 30~60회 | 주 3회 경마일 기준 |

> **총 일일 호출량 예측**: 최대 약 1,700회 (경마 시행일 기준)  
> **비경마일**: 새벽 벌크싱크 약 46~92회 (2경주장 × 23 API)

## ■ 3. 화이트리스트 등록 요청 API 목록

### 3-1. API187 — 경마경주정보 (경주 목록)

| 항목 | 내용 |
|------|------|
| **API ID** | API187 |
| **API명** | 경마경주정보 |
| **엔드포인트** | `/B551015/API187/raceInfoList` |
| **요청 파라미터** | meet(경마장코드), rc_date(경주일자 YYYYMMDD) |
| **활용 목적** | 당일 경주 목록 조회 — 경주 번호, 거리, 출발시각 등 기본 정보 취득 |
| **현재 장애 현황** | **응답 없음 / HTTP 403 반복** — 서비스 키 인증 후에도 빈 응답 반환 |
| **대체 수단** | 없음 — 경주 목록 조회 대체 API 미존재 |
| **등록 필요성** | 최우선 필수 — 이 API 없이는 당일 경주 정보 일체 조회 불가 |

**에러 증거 (Tab3 CSV 덤프에서 발췌):**
```
timestamp,api_id,error_type,http_status,response_body
[CSV 첨부 파일 참조 — admin_whitelist_errors_YYYYMMDD.csv]
```

### 3-2. API26_2 — 출전마 상세정보

| 항목 | 내용 |
|------|------|
| **API ID** | API26_2 |
| **API명** | 출전마 상세정보 |
| **엔드포인트** | `/B551015/API26_2/raceHorseInfo` |
| **요청 파라미터** | meet, rc_date, rc_no(경주번호) |
| **활용 목적** | 경주별 출전마 목록, 마번, 기수명, 조교사명, 배당률, 출발시각(stTime), 두수(dusu) 조회 |
| **현재 장애 현황** | **간헐적 타임아웃 / 빈 item 배열 반환** — 정상 서비스 키 사용에도 장애 지속 |
| **대체 수단** | 벌크 캐시(API8_2/API12_1) 부분 대체 가능하나 stTime/dusu 필드 미포함 |
| **등록 필요성** | 필수 — 출전마 데이터 없이는 AI 스탯 분석 엔진 작동 불가 |

### 3-3. API4_3 — 경주기록 (RACE RESULT)

| 항목 | 내용 |
|------|------|
| **API ID** | API4_3 |
| **API명** | 경주기록 |
| **엔드포인트** | `/B551015/API4_3/raceResult` |
| **요청 파라미터** | meet, rc_date, rc_no, hr_no(마번) |
| **활용 목적** | 출전마별 과거 경주 기록(시간, 순위, 거리별 성적) → S_speed 지표 산출 핵심 소스 |
| **현재 장애 현황** | **호출 빈도 제한(Rate Limit) 추정** — 출전마 10두 이상 조회 시 일부 응답 누락 |
| **대체 수단** | 없음 — 말별 경주기록 대체 API 미존재 |
| **등록 필요성** | 필수 — 스탯 엔진의 속도 지표(S_speed) 산출 불가 |

| 항목 | 내용 |
|------|------|
| **API ID** | trnweekentry |
| **API명** | 조교사 차주 출전 예정마 조교정보 |
| **엔드포인트** | `/B551015/trnweekentry/gettrnweekentry` |

| **등록 필요성** | 권장 — TrainerFocus 지표 정확도 향상 |

## ■ 4. API 장애 현황 증거 자료 (첨부 파일 안내)

### 4-1. 첨부 파일 생성 방법
앱 내 관리자 패널(Admin Data Panel) → Tab 3(에러 로그) → **"화이트리스트 신청용 CSV 내보내기"** 버튼 클릭

생성되는 파일: `admin_whitelist_errors_YYYYMMDD_HHMMSS.csv`

### 4-2. CSV 파일 구조
```csv
# 경마통 RE-RACE AI SIMULATOR — 관리자 에러 로그
# 생성일시: YYYY-MM-DD HH:MM:SS
# Mode: 화이트리스트 신청용 4대 핵심 API 필터
# Target APIs: API187, API26_2, API4_3, trnweekentry
# 총 에러 건수: N건

순번,발생시각,API_ID,에러유형,HTTP_상태코드,요청_파라미터,응답_본문(요약),재시도횟수
1,2025-01-15 04:12:33,API187,HTTP_403,403,"meet=1&rc_date=20250115","접근 거부",3
2,2025-01-15 04:12:35,API187,EMPTY_RESPONSE,200,"meet=2&rc_date=20250115","item:[]",3
3,2025-01-15 09:31:22,API26_2,TIMEOUT,408,"meet=1&rc_date=20250115&rc_no=1","요청 타임아웃",2
...
```

### 4-3. 에러 유형 분류 (CSV 에러유형 필드 기준)

| 에러유형 코드 | 설명 | 해당 API |
|-------------|------|----------|
| `HTTP_403` | 서비스 키 인증 거부 | API187 주요 |
| `EMPTY_RESPONSE` | 정상 200 응답이나 item 배열이 빈 상태 | API187, API26_2 |
| `TIMEOUT` | 응답 10초 초과 | API26_2, API4_3 |
| `RATE_LIMIT` | 단시간 다수 호출 시 응답 지연/누락 | API4_3 |
| `XML_ONLY` | JSON 요청에 XML만 반환 | trnweekentry |
| `PARSE_ERROR` | 응답 파싱 실패 (비정형 응답) | 전체 |

## ■ 5. 기술적 근거 — 화이트리스트 필요성

### 5-1. 현재 5단계 폴백 아키텍처로 인한 과부하
API 장애로 인해 다음과 같은 다중 재시도가 발생하여 오히려 API 서버 부하를 증가시키는 악순환이 발생하고 있습니다:

```
TIER-1: API 직접 호출 (1회)
  ↓ 실패
TIER-2: 파라미터 변형 재시도 (3~4회)
  ↓ 실패  
TIER-3: XML 폴백 호출 (1회)
  ↓ 실패
TIER-4a: 로컬 캐시 조회
TIER-4b: 벌크 캐시(API8_2/API12_1) 보강
  ↓ 캐시 없음
TIER-5: Mock 데이터 반환 (사용자에게 부정확한 정보 제공)
```

**화이트리스트 등록 후 예상 효과**: TIER-1 직접 성공 → 재시도 99% 감소 → API 서버 부하 감소

### 5-2. 사용자 경험 손실
- 경주 당일 출전마 정보를 실시간으로 조회하지 못하고 Mock(가상) 데이터를 표시
- AI 스탯 분석 정확도 저하: 실제 과거 경주기록 없이 추정치 사용
- 경주 목록(API187) 장애로 인한 경주 번호 하드코딩 필요

## ■ 8. 신청 경로 및 제출 방법

### 공공데이터포털 화이트리스트 신청
1. **접속**: https://www.data.go.kr
2. **로그인** 후 → **마이페이지** → **활용신청**
3. 해당 API 검색 (예: "경마경주정보") → **활용신청** 버튼 클릭
4. 활용목적 입력란에 본 신청서 내용 복사 붙여넣기
5. **첨부파일**: `admin_whitelist_errors_YYYYMMDD.csv` 업로드

### 한국마사회 직접 문의 (병행 권장)
- **KRA 공공데이터 문의**: 공공데이터포털 > 해당 데이터셋 > 문의하기
- **한국마사회 대표**: 02-509-1000
- **이메일 문의**: data.go.kr 해당 API 페이지 내 제공기관 연락처 활용
